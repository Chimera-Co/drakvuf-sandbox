## 1. What the platform is

- "Malware Shodhak 360, Malware Analysis Platform", version badge **v4.0**, ISEA logo, "Powered by E-Samarthak";
  footer "Centre for Development of Advanced Computing (C-DAC), Hyderabad"; PDF reports say "Report generated by
  C-DAC, Hyderabad" **[A]**.
- Pitch: "static and dynamic analysis platform for Windows executables, Android APKs, URLs and network traffic.
  Powered by indigenous algorithms with automated threat intelligence" **[A]**.
- Pages: Home, Analyze (File / URL / Network tabs), Reports (Recent Analysis), a report page per task, user manual,
  feedback, an admin dashboard route **[B]**. Six video tutorials (static, dynamic, APK, URL, network, report
  generation; 1:07–2:47) **[A]**.

## 2. Analysis services (the engines behind each tab)

The report page picks a renderer by engine name **[B]**:

| Engine key in the client | Shown as | Input accepted | Notes |
|---|---|---|---|
| `eSamarthak` | Static | `.exe`/`.dll` inside the archive | In-house static engine ("E-Samarthak Analysis Engine"); "eSamarthak only supports .exe or .dll files inside the zip." **[B]** |
| `Cuckoo` | Dynamic | `.exe`/`.dll` inside the archive | Report shows "Analysis machine: cuckoo1", "Version 2.0.7" **[A]**, i.e. Cuckoo Sandbox 2.0.7 with an in-guest agent **[I]** |
| `mobSF` | Static APK | `.apk` inside the archive | MobSF report ("This report provides static analysis of the Android APK file using MobSF framework") **[B]**; APKiD section **[B]** |
| `mobsfDynamic` | Dynamic (APK) | – | A "MobSF Dynamic Analysis Report" renderer exists in the client **[B]**; not seen in the assets |
| `elfStatic` | ELF Static | ELF | Renderer exists **[B]**; not seen in the assets |
| `Url Analysis` | URL | URL or bare domain | Reachability, rank, WHOIS, TLS, headers, cookies, robots/sitemap, Wayback **[A][B]** |
| `Pcap Analysis` | Network | `.pcap`/`.pcapng`, max 5 MB | Uploaded capture, not traffic from a detonation **[A]** |

## 3. Submission and queue

- **File:** choose Static *or* Dynamic (radio buttons), upload a **password-protected** `.zip`/`.rar`/`.7z`, max
  25 MB, type the archive password **[A]**. The client rejects an archive without a password ("ZIP is not
  password-protected. Please upload a password-protected archive.") **[B]**.
- **Guards:** "Analysis limit reached", "Too many upload attempts", "This file is already being analyzed" **[B]**:
  per-user rate limiting and de-duplication of identical in-flight files **[I]**.
- **Claim:** "No files are retained after processing. All analysis tasks are isolated." **[A]**
- **Recent Analysis:** counters (showing / completed / in progress / pending), filters by status, analysis type,
  file type and date range, free-text search by file name, hash or service, a View action per row **[A]**.
- **Speed seen:** one dynamic run of 37 s (started 12:02:20, ended 12:02:58) **[A]**.

## 4. Reports, engine by engine

Every report page has a left-hand section menu, a "Data Loaded" badge and a **Download Report** button that
produces a PDF in the browser (the client bundles `@react-pdf/renderer`) **[A][B]**.

| Report | Sections **[A]** | Score shown **[A]** |
|---|---|---|
| Static (PE) | File Summary (properties extracted / with data / missing); Capabilities & TTPs (capa results, suspicious APIs by category, ATT&CK, MBC, IOCs); File Structure (headers, sections, imports, resources, security; counts and high-entropy sections); Detection & Analysis (plugin detections, heuristics); Hashes & Similarity (MD5, SHA-1, SHA-256, SHA-3, ssdeep, imphash) | Risk **32/100** ("Low Risk") on one sample |
| Dynamic (Cuckoo) | Overview (file info, hashes, duration, machine, version); Static Analysis; Behaviour (API call statistics, registry operations, loaded modules); Process Tree; Network (UDP, DNS, HTTP, capture hashes); Extracted Buffers; Dropped Files; Debug/Errors (errors, actions, logs) | **2/10** "Low Risk" on one sample, **0/10** on another |
| APK (MobSF) | Overview & identity; components and attack surface (exported activities, services, receivers, providers); permissions (dangerous count); security findings; certificate and signing; extracted IOCs | Security score **50/100** ("Moderate risk") and 60/100 on two apps |
| URL | IP, global rank, response time, status; availability, Wayback, domain registration; TLS/SSL certificate and grading; HSTS and other header recommendations; WHOIS, cookies, robots/sitemap | Pass/issue badges |
| PCAP | Totals, packet-length statistics and distribution, bandwidth; IP analysis, DNS, port usage, protocols, HTTP, traffic flow and time flow, user agents, geolocation, packet list | – |

Observed details that matter for the comparison:

1. **Static and dynamic are separate submissions.** The dynamic report's "Static Analysis" section showed "Static
   Analysis Data Not Available" in the recording **[A]**. There is no combined verdict across engines **[A]**.
2. **Each engine has its own scale:** /10 for dynamic, /100 risk for static, /100 security score for APK **[A]**.
   None of the reports seen explains how the number was reached beyond the findings list **[A]**.
3. **Much of the static report is raw structure** (every DOS/PE header field, e.g. `e_ovno`, `e_oemid`), shown in
   the web view and repeated over ~10 PDF pages **[A]**. The interpretation layer (capa, ATT&CK, MBC) is the
   useful part.
4. **Accuracy figures in the interface** ("99.8%", "98.5%", "99.2%" per engine; "Detection Rate: Industry-leading
   accuracy") are fixed strings in the client **[B]**. We found no published method or dataset behind them, so
   CHIMERA's benchmark does not compare against these numbers.
5. **Dynamic coverage:** Windows `.exe`/`.dll` only, via Cuckoo 2.0.7 **[A][B]**. Cuckoo 2 is the legacy
   line **[K]**; the maintained successor is Cuckoo 3 by CERT-EE, which its own README calls not production ready
   **[V]** (`competitive-landscape.md`, Cuckoo 3 profile).

## 6. What CHIMERA should do with this (feeds `roadmap.md`)

By 31 Oct, in order of value for effort:

1. **One report that joins static, dynamic and the verdict**, with every claim linked to its evidence. This is the
   largest visible gap in MS 360 and the place CHIMERA is already ahead.
2. **Static depth on the file itself:** capa with ATT&CK/MBC on the submitted file (today capa runs on memory dumps
   in postprocess), showing the imphash/TLSH/ssdeep values we already compute, and a real YARA ruleset.
3. **One scale, explained:** malicious / benign / indeterminate plus the reasons, instead of three different scores.
4. **Print-ready export** of that report.

Not by 31 Oct: APK, URL mode, PCAP upload, multi-user rate limits, tutorial videos.

Things not to copy: unexplained accuracy figures; per-engine scores on different scales; pages of raw header
fields without interpretation.
