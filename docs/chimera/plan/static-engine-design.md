# CHIMERA static engine: audit and delivery design

25 October 2026 · Group 3 · deadline: 31 October 2026

## Decision

Keep the existing container and PE/ELF parsers. Before adding breadth, fix result status, prefix hashes, missing-dependency failures, evidence provenance and the interpretation of a zero score. Add a pinned ReversingLabs rules bundle as the deadline default; treat Office inspection as the first optional format addition. Defer disassembly, emulation and recursive extraction. These are proposed engineering decisions, not implemented changes.

Evidence convention: **[V]** means a primary external source read during this audit; **[S]** means a secondary source; **[K]** means background knowledge not re-verified. Repository observations use `path:line`; implications are explicitly identified as audit inferences. Performance budgets below are design proposals, not measured product performance. No external benchmark is presented as a CHIMERA measurement.

Scope: source inspection, public text documentation and local offline tests only. No repository files were intentionally changed; no image was built, no deployment inspected, no service or VM started, and no sample downloaded. Read the four context documents before drafting: `docs/chimera/ecosystem-and-market.md:1`, `docs/chimera/static-analysis.md:1`, `docs/chimera/classifier-interface.md:1`, `docs/chimera/threat-model.md:1`. Historical host-test claims in those documents were not re-verified here. `graphify query` was the first codebase lookup; actual files take precedence over its graph.

### 1.2 `chimera-static/1` contract

Normal output has `schema`, `analyzer_version`, UTC `started`, `errors[]`, `findings[]`, `hardening`, `file`, `type`, `universal`, stage `timings_s`, `score`, `level`, `duration_s`; optional `pe`, `elf`, `pdf`, and `ml.ember_v3`. `file` combines name, original stat size/mode/executable bits/truncation and hashes. A finding contains `id`, `title`, `severity`, **string** `evidence`, `attack[]`, **string** `source`. No confidence, tool version, rule checksum or byte-span provenance is required. Evidence: `static_analyzer/chimera_static/analyze.py:26`, `:45`, `:67`, `:93`, `:105`, `:136`, `:144`; `safety.py:75`.

Fatal CLI output instead contains `schema`, `analyzer_version`, singular `error`, `hardening`, `started`, and may omit normal arrays and score. The wrapper adds `container` (engine/image/exit/stderr) and the worker adds `job` (analysis ID/wall time). Some wrapper errors have only schema/error/container. This is a family of shapes, not a formally validated schema. Evidence: `static_analyzer/chimera_static/__main__.py:44`; `drakrun/analyzer/static/sandbox.py:112`, `:124`, `:126`; `worker.py:60`.

Scoring is additive **once per finding ID**, with info=0, low=4, medium=12, high=25; cap 100. Level is high ≥60, medium ≥35, low ≥15, otherwise **clean**. One high finding scores 25 and therefore has a low aggregate level; three low findings score 12 and still say clean. This is a heuristic index, not a calibrated probability. Evidence: `static_analyzer/chimera_static/analyze.py:14`, `:19`, `:138`.

YARA severity accepts string `severity` or `threat_level`; unrecognized values, including numeric severity metadata, become medium. YARA metadata/tags/namespace are kept in `universal.yara`, but matching strings/offsets are discarded and finding ID uses only rule name. Evidence: `static_analyzer/chimera_static/analyze.py:87`; `universal.py:213`.

### 1.3 Worker, containment and downstream use

Upload stages a separate copy and enqueues `chimera-static`; the worker deletes input in a `finally`, atomically stores JSON and removes container output. Static is disabled by default; configured defaults are 90 s, 2048 MiB, 1 CPU, 32 PIDs, uid/gid 65534, 120 s classifier wait and 32 MiB accepted JSON. Evidence: `drakrun/analyzer/static/worker.py:41`, `:52`; `drakrun/lib/config.py:105`.

The image is Python 3.11-slim-bookworm, uses a compiler-containing build stage, keeps libmagic in runtime, removes pip/setuptools/wheel and copies the rules directory. Requirements pin pefile, signify, pyelftools, python-magic, yara-python, py-tlsh, ppdeep, numpy/sklearn, plus oscrypto at a Git commit. Base images and package hashes are not digest-locked. Evidence: `static_analyzer/Containerfile:7`, `:15`, `:23`, `:32`; `static_analyzer/requirements.txt:1`.

The command applies no network, read-only root, dropped capabilities, no-new-privileges, unprivileged UID, cgroup limits, 64 MiB noexec tmpfs, and read-only input/noexec Podman mounts. CLI sets core/CPU/open-file/file-size/address-space/process limits and prctl flags before analysis. These controls reduce blast radius but are not evidence that a container escape is impossible. Evidence: `drakrun/analyzer/static/sandbox.py:37`; `static_analyzer/chimera_static/__main__.py:39`; `safety.py:42`. RLIMIT_NPROC=0 is an important integration constraint: adding subprocess-based tools to the current hardened Python process will fail under the intended unprivileged setup (`safety.py:53`).

Classifier postprocessing waits for static output, writes it into `features.json`, runs the model, then stores classification and metadata. Evidence: `drakrun/analyzer/postprocessing/plugins/classify_sample.py:10`. Current deployed model source handles singular static error as unknown, chooses format-specific calibrated models when a vector and matching dimension exist, otherwise converts rule score into a surrogate probability with half weight and a suspicious-only ceiling. It checks vector dimension, not extractor identity or stage completeness. Evidence: `classifier/chimera_clf/deploy_model.py:150`, `:164`, `:174`, `:188`, `:208`. Fixed fusion weights are explicitly unfit to paired runs (`deploy_model.py:220`).

**capa already exists, but on a different evidence surface:** postprocess loads ATT&CK-tagged rules, optionally analyzes DRAKVUF logs into `ttps.json`, and optionally analyzes process memory dumps into `dumps_ttp/`. Dump analysis selects .NET or Vivisect backend, explicitly Windows OS, with a multiprocessing pool. It is not a call to capa on the original upload inside the static container. Evidence: `drakrun/analyzer/postprocessing/plugins/capa_plugin/capa_processor.py:184`, `:219`, `:238`, `:310`, `:336`, `:352`. Keep disk-static capability evidence distinct from recovered-memory and dynamic evidence.

Offline HTML currently embeds metadata, report, process tree and screenshots, without explicitly loading `static.json` or `features.json`; static evidence will need an explicit export path. Evidence: `drakrun/analyzer/postprocessing/plugins/generate_html_report.py:20`. Report generation precedes classification in the plugin list (`drakrun/analyzer/postprocessing/plugins/__init__.py:104`, `:108`).

### 1.4 Error handling and prioritised defects

Stages catch MemoryError and ordinary exceptions and retain other results; heavy stages are skipped if elapsed time already exceeds 80% of the budget. This does not interrupt a running parser, and YARA compilation is outside its match timeout. Fatal reads, unguarded whole-file entropy and imports outside `stage()` can still terminate the overall operation. CLI codes are 0 written with possible stage errors, 2 refusal, 3 internal failure; module imports happen before the CLI try. Evidence: `static_analyzer/chimera_static/analyze.py:49`, `:67`, `:75`, `:108`, `:133`; `universal.py:199`; `__main__.py:23`, `:39`.

| Priority | Confirmed issue / consequence | Evidence and proposed action |
|---|---|---|
| P0 | **No rules shipped: confirmed.** The directory contains only README.txt. The Dockerfile explicitly calls it empty; missing rules produce a stage error and zero YARA findings. | `static_analyzer/rules/README.txt:1`; `static_analyzer/Containerfile:32`; `universal.py:203`. Ship a pinned tested bundle; expose rule count and scan status. Do not show “no matches” when scanning never ran. |

Other correctness cautions: `tls_callbacks` checks the callback-table pointer, not actual callbacks (`plugins/pe.py:242`); “valid signature” is one offline verification outcome, not a current online revocation or reputation verdict (`plugins/pe.py:61`); ELF static/stripped and PE packer/entropy hints can also describe benign programs. The last point is an audit inference from the heuristics, not a measured false-positive rate.

## 2. Candidate engines under the container budget

### 2.1 How to interpret cost and maintenance

**Installed size and typical runtime are not verified for any candidate in this exact image.** No tools were installed or benchmarked. Dependency closure, rules, native libraries, caches and unpacking make wheel/download bytes unsuitable as installed-size claims. The table gives honest artifact-size proxies where metadata was available; “unmeasured” means no trustworthy installed-size number. All runtime cells are proposed stage kill budgets, **not typical runtimes**; typical runtime remains unverified. Measure p50/p95, cold-start/compile cost, peak RSS and image delta on benign fixtures before enabling a new tool.

Maintenance is a source snapshot, not a support guarantee: release date when available, otherwise an explicit weaker signal. PyPI JSON is maintainer-published artifact metadata; GitHub release/API metadata was read without downloading assets. MB below means decimal bytes / 1,000,000. Recommendations and risk assessments are this audit's engineering judgments.

### 3.2 Budgets and isolation

Proposed sequential baseline wall allocation: startup/preflight 5 s; read/identify/full hashes 10 s; universal indicators 10 s; YARA 15 s; one applicable format parser 15 s; EMBER 20 s; validation/write 5 s; reserve 10 s. Total **90 s**. Unused stage allowance returns to the common deadline; these are caps to validate on benign fixtures, not promised runtimes. A parser that reaches its allowance returns timeout/partial with already collected evidence.

For 31 Oct retain the single hardened library process and an external wall watchdog; do not weaken RLIMIT_NPROC=0 to make an optional CLI work. It currently cannot preserve all in-memory partial evidence after native crash or hard kill. Write atomic bounded checkpoints between stages, so the wrapper can retain a known-valid partial result and append terminal failure status.

Future CLI/deep profile: trusted minimal supervisor launches fixed tool commands in isolated child containers or separately constrained workers, one at a time. The parent need not import sample parsers. Keep each parser's no-network/UID/capability/read-only limits, bounded process group kill and byte-capped stdout/stderr. Set a writable scratch HOME/cache only inside bounded tmpfs, not host home; no sample-controlled paths/options. This explicitly changes the process model and requires new isolation tests. Do not quietly remove the existing no-process restriction.

Proposed baseline caps: reject input >256 MiB; 1000 findings, 100 YARA matches, 10 matched spans per rule, 256 displayed bytes per span, 100 IOCs/category, 32 MiB JSON max. ZIP listing: 1000 entries and 1 MiB total name metadata, with no content extraction. Later extraction: depth 2, 100 files, 16 MiB/member, 32 MiB actual total expansion, ratio guard 100:1 plus hard total-byte limits; skip oversized dictionaries/solid blocks and encrypted content. These are initial policy values, not format-library guarantees. Children get synthetic IDs/paths and SHA-256; no automatic child detonation. Parent and child evidence must remain attributable.

Pin image digest, Python/wheel hashes, rules manifest and adapter versions; retain SPDX-like component inventory and licences in the image. Record effective hardening failures as coverage/status warnings; fail closed if mandatory isolation is absent. Keep one static job at a time alongside at most one dynamic analysis, and measure host memory pressure before claiming this meets the laptop budget. No such host measurement was performed here.

## 4. Proposed `chimera-static/2`

### 4.1 Compatibility and evidence rules

Preserve all existing field names and types, including **string** `finding.evidence` and **string** `finding.source`; add structured `evidence_details` and `source_details` rather than changing either into objects. Preserve `attack[]` and add `references[]`, not a conflicting second ATT&CK field. New confidence is numeric 0..1, meaning confidence that the indicated property is present, **not probability of malware**. Severity expresses relevance/impact if malicious, separate from confidence.

Changing `schema` to `/2` is not wire-compatible with existing consumers: `drakrun/analyzer/static/sandbox.py:122` and `worker.py:79` explicitly accept only `/1`. Migration order: (1) validators/readers accept both schemas with strict per-version validation; (2) retain a `/1` compatibility serializer for older clients; (3) emit `/2` after all consumers pass fixture tests. A `/1` projection keeps legacy fields/score/findings and represents incomplete fatal failures through existing singular `error`; the v2 structured document remains authoritative. Do not simply relabel a `/2` object as `/1`.

Required additions:

- `status`: `complete|partial|error|unsupported`; a complete run means all applicable required stages completed, not “benign.” Optional unsupported stages do not invalidate supported core evidence, but must appear in coverage.
- `mode`: `static|combined`; `coverage[]`: tool/stage, applicability, `ok|error|timeout|skipped|unsupported|not_applicable`, bytes inspected, truncation and reason; `errors[]` gains stable code/fatal fields while retaining stage/error text.
- `input`: upload SHA-256, size, actual bytes read, whole-file hash scope; if a full hash is unavailable, do not put a prefix digest in `file.sha256`. `file` retains existing fields. No missing/null values may become an invented all-zero digest.
- `provenance`: image digest, analyzer revision, effective limits, ruleset source/ref/digest/licence manifest and tool versions. Record extractor identity/dimension/model feature contract independently of overall schema.
- Every finding: legacy six fields plus `confidence`, `evidence_details[]`, `source_details`, `references[]`. `evidence_details` holds artifact ID, offset space, byte offset/length or explicit null with reason, escaped string/hex excerpt, optional object/stream/member identity and derivation chain. Decoded stream offsets must never masquerade as original-file offsets.
- `source_details`: tool, version, adapter version and rule identity/namespace/ruleset digest when applicable; retain upstream author/licence/reference metadata. `attack` is a potential technique association, never proof of observed execution.
- `assessment`: versioned heuristic policy, score scope, completeness, rationale and correlated-group contributions. Retain legacy `score`/`level` for consumers but label “clean” as legacy “no scored indicators”; a partial result must not vote benign.

Validate enums, finite numbers, integer bounds, string lengths, list sizes, unique IDs and span bounds. Reject NaN/Infinity, booleans in numeric fields, unknown schema versions and malformed tool data. Allow bounded unknown extension fields only in a namespaced extensions object. Tool-produced JSON is untrusted input, even inside the container.

Finding identity proposal: stable `source/rule` ID plus separate instance/artifact ID. Deduplicate scoring by evidence family/group, preserving all observations. For the deadline retain the old heuristic score as `legacy-additive-v1` to avoid silently changing trained fusion behavior, but gate all negative evidence on coverage. Introduce a separately evaluated grouped policy later; do not train or claim calibrated confidence from hand-set weights.

## 5. Classifier, report and static-only integration

**Classifier:** normalize v1/v2 through one bounded adapter before model loading. Validate upload hash binding, extractor identity/dimension, successful feature extraction, and vector finiteness. Retain the frozen EMBER vector as the existing model input; new evidence fields initially improve explanations and coverage gating, not the trained feature space. Existing rules-only ceiling at suspicious is worth preserving (`classifier/chimera_clf/deploy_model.py:174`). Missing/failed/unsupported static analysis contributes unknown, never zero-risk/benign; partial positive evidence can still support a qualified suspicious explanation. Revalidate fixed-weight fusion on paired benign/malicious evaluation data later; no accuracy claim follows from adding more tools.

**Final report:** store the exact static JSON alongside analysis artifacts, with a bounded summary in report metadata and explicit completion time. UI/export should show status, analyzed format/bytes, coverage/skips/errors, heuristic score policy, ML component, signature limitations, YARA rule/source/licence, and evidence spans with tool versions. Link capability ATT&CK associations separately from observed dynamic TTPs. Existing upload stages static and then enqueues dynamic (`drakrun/web/api.py:90`); this branch must change before claiming static-only support.
